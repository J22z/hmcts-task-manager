# Task Manager API Documentation

This document explains the REST API developed for the HMCTS Task Manager.

The backend is built using Java and Spring Boot, with an H2 database for storing tasks.

## Base URL

http://localhost:8080

All task endpoints begin with `/api/tasks`.

## Task Properties

Each task contains:

| Field | Type | Description |
|---|---|---|
| id | Long | Unique ID generated by the database |
| title | String | Required task title (maximum 200 characters) |
| description | String | Optional task description |
| status | String | Current task status |
| dueDate | DateTime | Required due date and time |

Supported statuses:
- PENDING
- IN_PROGRESS
- COMPLETED

## 1. Create a Task

**POST** `/api/tasks`

Creates a new task. The backend automatically sets its status to PENDING.

### Example Request

```json
{
  "title": "Review court documents",
  "description": "Check evidence before the hearing",
  "status": "PENDING",
  "dueDate": "2026-11-10T14:30:00"
}
```

The current implementation requires a status in the request, although the backend sets new tasks to PENDING.

### Successful Response — 201 Created

```json
{
  "id": 1,
  "title": "Review court documents",
  "description": "Check evidence before the hearing",
  "status": "PENDING",
  "dueDate": "2026-11-10T14:30:00"
}
```

Invalid task information returns 400 Bad Request.

## 2. Retrieve All Tasks

**GET** `/api/tasks`

Returns all tasks stored in the database.

### Successful Response — 200 OK

```json
[
  {
    "id": 1,
    "title": "Review court documents",
    "description": "Check evidence before the hearing",
    "status": "PENDING",
    "dueDate": "2026-11-10T14:30:00"
  }
]
```

If no tasks exist, the API returns an empty array.

## 3. Retrieve a Task by ID

**GET** `/api/tasks/{id}`

Retrieves a specific task using its ID.

### Example

`GET /api/tasks/1`

### Successful Response — 200 OK

```json
{
  "id": 1,
  "title": "Review court documents",
  "description": "Check evidence before the hearing",
  "status": "PENDING",
  "dueDate": "2026-11-10T14:30:00"
}
```

If the task does not exist, the API returns 404 Not Found.

## 4. Update Task Status

**PATCH** `/api/tasks/{id}/status`

Updates the status of an existing task.

### Example Request

`PATCH /api/tasks/1/status`

```json
{
  "status": "COMPLETED"
}
```

### Successful Response — 200 OK

```json
{
  "id": 1,
  "title": "Review court documents",
  "description": "Check evidence before the hearing",
  "status": "COMPLETED",
  "dueDate": "2026-11-10T14:30:00"
}
```

Only PENDING, IN_PROGRESS and COMPLETED are accepted.

Invalid statuses return 400 Bad Request.

If the task does not exist, the API returns 404 Not Found.

## 5. Delete a Task

**DELETE** `/api/tasks/{id}`

Deletes an existing task from the database.

### Example

`DELETE /api/tasks/1`

### Successful Response — 204 No Content

The task is deleted successfully.

No response body is returned.

If the task does not exist, the API returns 404 Not Found.

## HTTP Status Codes

| Code | Meaning |
|---|---|
| 200 | Request successful |
| 201 | Task created |
| 204 | Task deleted |
| 400 | Invalid request |
| 404 | Task not found |

## Validation

The API includes validation to prevent invalid task information.

- Titles cannot be empty.
- Titles cannot exceed 200 characters.
- Due dates are required.
- Descriptions are optional.
- Status updates must use a supported value.

## Database

Tasks are stored using an H2 file-based database.

The database is configured in `application.properties`.

This allows tasks to remain saved when the application is restarted.
